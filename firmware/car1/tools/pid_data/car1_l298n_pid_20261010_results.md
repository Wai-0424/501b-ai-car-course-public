# 車一 L298N 速度 PID 架高測試（2026-10-10）

## 測試邊界

車輛架高、後輪無地面負載；BMduino 以 e-Link32 Pro 刷寫，USB COM25 送具 XOR8 校驗與 `seq` 的 `CMD`，每 100 ms 讀取 `STA`。下表取每組測試最後約 1.5 s 的平均。轉速是編碼器依**兩輪暫用 1560 tick／輸出軸轉**換算；M2 過去手轉曾量到約 1320 tick／轉，尚未以獨立轉速計排除編碼器倍率或接線問題。表中的 M1 是 D8／ENA／右輪，M2 是 D9／ENB／左輪。

韌體參考車二的 20 ms PID、duty→tick 查表前饋、EMA 濾波、duty 斜率限制與故障停車。車一把 100% 命令設為約 180 RPM，非零 1–100% 映射約 55–180 RPM；0 關閉 Enable。PID 參數為 Kp=0.50、Ki=0.04（每 20 ms 積分），積分修正限制約 ±16 duty，最大斜率 8 duty／20 ms。

## 保護與換向

- 30% 雙輪運轉時停止送有效 `CMD`，改送有正確 checksum 但缺少 `seq` 的封包：最後一個有效命令後約 523 ms，兩路 duty 歸零，且未重新啟動；`ackseq` 與故障旗標未異常。[逐筆紀錄](car1_pid_watchdog_20261010_154643.csv)。
- 初版以固定 300 ms 空轉等待直接換向，在 30% 測試中約 351 ms 即恢復反向 duty；當時輪子仍以約 46/53 RPM 滑行，故此等待**不足以單獨保護換向**。[逐筆紀錄](car1_pid_reverse_20261010_155135.csv)。
- 已編譯改良版：換向前除等待至少 300 ms，還需兩輪各自的編碼器連續三個 20 ms 週期低於 5 tick／週期（約 9.6 RPM）才恢復 duty。**此版目前尚未刷寫與實測：本機 e-Link32 Pro 與 BMduino COM25 同時從裝置清單消失。**重新接上後需刷入 `build/car1_l298n_pid_candidate`，重跑低速直接換向、100% 穩態與 watchdog 測試，完成後再更新此報告。
