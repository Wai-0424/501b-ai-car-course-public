# 車 1 L298N 驅動板遷移與重新校正計畫

> 狀態：待執行。這份計畫以 bmduino_car_control/bmduino_car_control.ino
> 的目前程式常數為基準；接線與實車結果優先於歷史文件。

車 1 已由舊驅動板換成標準 L298N。雖然控制介面仍是兩組方向輸入加兩組
Enable PWM，但 L298N 的壓降、起轉死區、自由停止/煞車行為與正反轉動態都
可能不同。因此不能直接沿用舊板的前饋與 PID 校正值。

本計畫的原則是：先確認硬體訊號與編碼器，再量測新板的馬達曲線，最後才做
閉環 PID 與 Orin 整合。每一階段都要保留可追溯的原始量測資料。

## 1. 保留的既有硬體配置（待實車逐項確認）

目前正式程式的定義如下；L298N 若仍使用標準 IN1/IN2 + ENA、
IN3/IN4 + ENB 介面，這是遷移的初始映射。

| 邏輯通道 | 方向訊號 | 速度 PWM | 編碼器 | L298N 預期端子 |
| --- | --- | --- | --- | --- |
| 轉向 | PCA9685 CH0 | — | — | 不變，servo |
| M1 | PCA9685 CH1 / CH2 | BMduino D9 經雙級 74LS14 | D2 / D3 | IN1 / IN2 / ENA |
| M2 | PCA9685 CH4 / CH3 | BMduino D8 經雙級 74LS14 | D6 / D7 | IN3 / IN4 / ENB |

- PCA9685 使用 Wire1、位址 0x40，方向腳以 5 V 數位輸出工作。
- D8/D9 是 5 kHz 軟體 PWM，經雙級 74LS14 後保持正邏輯。不要改回
  analogWrite()；該腳位組的硬體 PWM 曾經實測不可靠。
- SerialBM 在目前來源碼設定為 Serial3；Orin UART 實體接線必須與它一併
  確認，不能只根據早期的 Serial1 文件。
- L298N 的 ENA、ENB 跳線帽必須拔除，才可由 D9/D8 的 PWM 控制。
- 邏輯地、BMduino/PCA9685 地與 L298N 地必須共地；第一次通電先以限流電源或
  保險絲保護。

## 2. 目前資料衝突：先量測，不可直接相信歷史描述

下列項目在不同歷史文件和目前程式間有矛盾，第一次診斷必須建立新的實測表：

| 項目 | 目前程式來源 | 歷史文件 | 本次處置 |
| --- | --- | --- | --- |
| M1 編碼器 | D2/D3 | 部分文件寫 D6/D7 | 逐輪手轉，記錄 A/B 相與正負 tick |
| M1/M2 對應實體輪 | M1=左、M2=右 | 部分文件寫 M1=右、M2=左 | 單輪短脈衝，用目視結果定義 |
| 安全轉向限位 | fwa ±60 | 已知問題文件寫 ±50 | 新馬達測試只需轉向回正；循線前再獨立確認 |
| Orin UART | Serial3 | 早期文件多為 Serial1 | 以實車線路與 UART 實測為準 |

## 3. 階段 A：L298N 低風險訊號診斷

新增獨立 sketch：car1_l298n_diagnostic/。不要覆寫
bmduino_car_control/，也不要第一步就燒錄既有的閉環或全量掃描程式。

診斷程式的要求：

1. 上電預設 ENA=ENB=0，兩組方向輸入固定在明確的安全狀態。
2. 一次只能選一顆馬達與一個方向；輸出短脈衝後自動回到零輸出。
3. 第一輪 duty 僅測 20、40、60，每點不超過 300 ms；操作者可在兩點間檢查
   方向、異音、發熱和驅動板指示燈。
4. 印出每次動作的通道、方向、duty、脈衝時間與 encoder delta。
5. 分別驗證 ENA/ENB=0、同向 IN、相反 IN 三種停止狀態的實際行為。
   L298N 的 coast/brake 真值表要依這片板的實際接線確認，不能沿用舊板註解。
6. 任何 I2C 寫入失敗、異常 encoder 計數或操作逾時，立即把兩個 PWM 都設為 0。

通過條件：每一輪正反轉方向可預期、另一輪保持靜止、encoder 有一致方向的
有效計數、停止後驅動板與馬達沒有異常發熱。

## 4. 階段 B：重新量測馬達與 L298N 曲線

現有 car1_motor_pwm_sweep_bidir_wire1/ 可作為後續基礎，但它會掃到
duty 255、每方向停留約 45 秒以上，不得當作新板首次測試。

在階段 A 通過後，複製並調整為 car1_l298n_pwm_sweep/：

1. 先限 DUTY_MAX=120、DUTY_STEP=10，逐顆輪、逐方向測試。
2. 若溫度、電流和回授正常，再分段提高上限，不能預設一定跑到 255。
3. 輸出 CSV：timestamp,motor,physical_wheel,direction,duty,rpm,ticks。
4. 量測起轉門檻、維持門檻、正反轉曲線、最大穩定 RPM，並加做 0→低速、
   低速→0、低速反轉的階躍測試。
5. 手動確認 TICKS_PER_REV；不能只因為舊版本使用 1550 就假設仍正確。

輸出資料放在本目錄新增的日期化 results/ 子目錄，並產生一份 CSV 與簡短的
校正報告。資料確認後，才可計算新的前饋查表或分段模型。

## 5. 階段 C：L298N 閉環控制

以階段 B 的資料建立 bmduino_car_control_l298n/，保留舊的
bmduino_car_control/ 做回退。初版要求：

- 使用新量測的前饋，不能沿用 FF_DEADBAND_M1/M2、FF_SLOPE_M1/M2 或
  MAX_TICKS_PER_INTERVAL_M1/M2。
- 先採 feedforward + P 控制，KI=0；確認每個目標速度均穩定後，才少量加入 I。
- 每輪獨立校正，正反轉若差異明顯應用方向別曲線或查表。
- 保留輸出 duty slew-rate 限制與反轉等待；但要以 L298N 的實際停車行為重新
  定義等待期間，不能把舊板的「煞車」註解直接視為已驗證的 L298N 煞車。
- 加入編碼器失效／堵轉保護：有非零目標但長時間無有效 tick 時切斷該輪，並在
  STA 回報 fault flag。這可借鑑車二 L298N 韌體的結構，但門檻要由車一量測決定。

架高驗證順序：10% → 20% → 40% → 60% → 正反轉 → 左右同步。每一步比較
目標 tick、實際 tick、duty、誤差與溫度。地面測試只在架高閉環結果穩定後開始。

## 6. 與 Orin／新 ROS 專案的銜接

L298N 韌體在架高測試通過前，Orin 只做 UART 監聽或送零速命令。新的
car1_bringup ROS 專案應在底層穩定後建立，並先只包含：

1. 唯一開啟 UART 的 uart_bridge_node。
2. /cmd_vel、速度/轉向限幅、watchdog、串列埠獨占與連線健康 topic。
3. L298N fault flag 的停車閘門與單元測試。

感知、D415 與循線控制放在第二階段，避免把驅動板、韌體、UART 與視覺問題混在
同一次實車測試裡。

## 7. 升格為正式版的條件

只有在下列條件全數達成後，bmduino_car_control_l298n/ 才取代正式運行版本：

- 接線表、實體輪對應、encoder 極性與 UART 連接已寫入文件。
- 正反轉、停止、兩輪同步與指令逾時均已架高實測。
- 各輪 duty→RPM 原始 CSV 與校正常數已提交。
- PID 在目標速度範圍內穩定，沒有持續震盪或積分累積。
- 堵轉／回授失效會自動切斷輸出。
- Orin bridge 能收到有效 STA，並在 link 或 fault 異常時使輪速歸零。
